1. 换个 Agent 就失忆：上下文怎么交接（见第 1 条）。这是本轮讨论量最大的中文帖：陈大黄一句提问拿到 25.3 万浏览、603 条回复、911 收藏，隔一天铁锤人再问一次，仍然收到 112 条回复。回复样本里已经长出了能抄的做法——放一份所有 Agent 都读的项目文件、移交时写下「试过且没用」的路、决策日志加文件树一起给，也出现了反对意见（一切都是文本，不必加限制）。对非程序员也有意义：换工具时的真实成本不是模型差价，而是把项目背景再交代一遍。最好的补充角度是把它整理成一份交接清单：目标、做到哪、已排除的方案、验收证据，四项各写什么。形式：独立原创帖，可附自己的交接模板。状态：可起草；所有做法均来自实际回复样本，没有官方方案。

2. Claude Code 团队怎么审 AI 写的代码（见第 2 条）。官方文章给了三个反直觉的数字：约九成代码由 Claude 写、六月到九月合并的 PR 翻倍以上、需要回滚的比例反而降四成多。中文转述已有四五条，但基本停在「五条要点」，没有讲清风险分级（低风险零人批、中风险一人、高风险两人）、「Agent 的批准不算人的批准」、「一次批准只管一个 commit」，也没有讲那个最值得抄的细节：评审器自己每天在历史事故集上跑分。最好的角度是拆「为什么代码越写越多，人反而审得越来越少」，并给一张风险分级表。形式：独立原创帖，或引用宝玉原帖做拆解。状态：可起草；关键数字已对照官方文章。

3. 便宜模型做动效视频，这次够用了（见第 3 条）。同一批实测对「便宜模型可以拿来出片」这点比较一致：花叔说动效水平「仅次于 Claude」，Tuturetom 说教程类动效「和 Opus 5.5 没啥区别」，但歸藏自己复测说细节和创造性「差 Opus 5.5 不少」。这个分歧恰好可以拿来做选题：不是「谁更强」，而是「哪些环节可以交给便宜模型」。最好的角度是给想用 AI 做视频、又不想按次付费的创作者一条具体路线：脚本与分镜仍用贵模型，动效与出片换成便宜模型加一套自己的 skill。形式：独立原创帖，可附自己的同题对比。状态：可起草、部分待实测；模型能力均为个人实测，官方只公布自测基准。
