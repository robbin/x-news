### OpenAI 公布 COBOL、Fortran、Visual Basic 进展，并开源 MultiLangBench

- 发生了什么：OpenAI 10-20 06:30 发帖称，最新模型在 COBOL、Fortran、Visual Basic 这类低资源编程语言的构建与迁移上更强，重点是理解几十年的业务逻辑、在现代化过程中保持原有行为不变，并向企业客户征集下一个要攻的语言与工作流。
- 为什么值得关注：这是把“写代码”拆成两个更接近企业预算的问题：从零构建（用 20 种语言写一个 SQLite 兼容引擎）和迁移（把 COBOL 迁到 C++、Java、Kotlin、Python、Rust 且行为不变）。后者直接对应银行、政府、保险的存量系统，也是 AI 编程最难拿到生产信任的地方。
- 核心原帖：[@OpenAI](https://x.com/OpenAI/status/2112310345863930168)（10-20 06:30，20.6 万浏览、2,478 赞、169 转、237 回复、116 引用）。
- 核验：对照 [OpenAI 官方博文](https://openai.com/index/low-resource-programming-languages/)（10-19 发布），确认两个评测的设计与分数：MultiLangBench 要求模型从零构建 SQLite 兼容数据库引擎，用数据库文件作为跨语言接口，GPT-6 Astra 在 20 种语言上平均测试通过率 87.4%，GPT-5.6 Sol 为 26.8%；分语言看 COBOL 从 10.9% 升到 72.1%、OCaml 25.6%→85.8%、Fortran 21.4%→83.5%、Visual Basic 27.5%→89.4%，Astra 在 19/20 种语言上超过 83%，COBOL 仍最难。GPT-6 Luna 平均 40.3%，每样本估计 API 成本 0.77 美元，对比 GPT-5.6 Sol 的 3.48 美元（约低 78%）。COBOL 迁移评测要求字节级输出一致、隐藏测试全过才算成功：GPT-6.1 Sol 低推理强度 86.6%，GPT-5.6 Sol 5.4%，成本约为后者 61%（博文开头写作“便宜 39%”，两种说法一致）；高推理强度 97.9%。评测集与分语言结果已放在 [openai/MultiLangBench](https://github.com/openai/MultiLangBench)。X 帖本身没有数字；“800 billion lines of COBOL”出自 CryptoBriefing 的报道，不是 OpenAI 原文，本文不引用。
- 判断：这是把“低资源语言”当成独立能力维度来做，而不是等通用 coding 能力自然外溢；COBOL 迁移用隐藏测试和字节级一致性，接近真实合规要求，方向比“能编译”更有意义。但所有分数都是厂商自测，OpenAI 也明确说生产迁移仍需专家复核；真正要看的是企业能否用这套评测复现自己的代码库，而不是平均通过率。

- 发生了什么：Meta 10-20 03:33 宣布发布 Muse Glimmer 技术报告。这是一个 30B 的开源权重模型，面向消费级硬件上的 agent 任务，4-bit 量化后可在单张消费级 GPU 上跑，官方称在同尺寸开源模型里工具使用和多步规划领先。报告披露了架构、从更大模型蒸馏的配方、量化与投机解码。

- 核心原帖：[@AIatMeta](https://x.com/AIatMeta/status/2112265822274302066)（10-20 03:33，6.8 万浏览、721 赞、91 转、73 回复、63 引用）；解读 [@kimmonismus](https://x.com/kimmonismus/status/2112270439078625477)（2.8 万浏览、241 赞）；团队成员 [@arreqe_ai](https://x.com/arreqe_ai/status/2112306216139685921)（303 浏览、6 赞）。

- 判断：Muse Glimmer 的看点不是“30B 能打 frontier”，而是“30B + 量化 + 投机解码 + 模拟环境蒸馏”这套把 agent 放到本地的工程组合。独立评测暴露的短板也很清楚：知识工作与校准差，幻觉率高。它适合当本地执行层，不适合当需要高可靠事实判断的最终裁决者。技术报告里的数据过滤规则，比榜单名次更值得其他团队抄。

- 发生了什么：Skyfall AI 10-20 01:58 发布 SKY-001，称其为第一个工程世界模型：在 CAD 和 BIM 任务上比 GPT-6 Astra 和所有被测前沿模型更快、更便宜、交并比（IOU）更高，具体是 51—125 倍快、150—210 倍便宜。它不做静态 3D 网格，而是把文本或 2D 草图拆成可执行的建模步骤，逐层分解零件再在 3D 里重组，输出可直接在 Autodesk Fusion 打开的设计。帖文称团队来自被微软收购的 Maluuba 深度学习实验室，做了 18 个月。

### Cloudflare 发布 Clairic：不做生成，只返回带类型的值

- 发生了什么：Cloudflare 10-20 02:06 发布 Clairic，称其为 System One 抽取模型，能从非结构化文本或图像中抽取、计算、估计、预测数值，单次前向、不生成 token，输出带类型的结果和置信度／概率。已在 Workers AI 以 @cf/cloudflare/clairic 预览，开放权重“很快”发布。
- 为什么值得关注：大量业务调用其实只是“把这封邮件里的金额、日期、订单号填进表”，用生成式 LLM 做既慢又按输出 token 计费。Clairic 把这类任务变成回归问题：不列选项、直接估连续值，还能给 p10—p90 区间，工程上更接近一个可审计的抽取器。
- 核心原帖：[@Cloudflare](https://x.com/Cloudflare/status/2112244042658423149)（10-20 02:06，5.3 万浏览、897 赞、106 转、27 回复、44 引用）；[@michellechen](https://x.com/michellechen/status/2112241006104244584)（9.5 万浏览、1,005 赞）；[@kevin_flansburg](https://x.com/kevin_flansburg/status/2112248553703928141)（3.2 万浏览、372 赞）。
- 核验：对照 [Cloudflare 文档](https://developers.cloudflare.com/workers-ai/models/clairic/)，确认 65,536 token 上下文、每百万输入 token 0.10 美元、无输出 token 计费、支持文本与最多 4 张图、字段类型含 text／number／date／list／estimate 等，返回 confidence、p_null 与区间；请求可把字段拆到多个 8,192 token 的并行 pass。对照 [PPC Land 对 Cloudflare 自测的逐项拆解](https://ppc.land/cloudflares-clairic-model-cuts-ai-pipeline-cost-49-in-its-own-test/)，确认官方自测的三段式理赔流水线：Clairic + Clef + GLM-5.3 端到端 19.3 秒，全用 GLM-5.3 为 61.7 秒（约 3.2 倍快）；每百万单成本 6,032 美元对 11,740 美元（省 49%）；抽取 + 决策合计 0.68 秒，GLM-5.3 同两步 38 秒。需要注意：博客的“更高准确率”没有通用 benchmark 支撑，只有一个理赔案例和 21 天预测测试，运行次数未披露；开放权重没有日期；kevin_flansburg 说“基于回归而非分类”，博客用 System One／decision model 的框架表述，未给回归公式细节。
- 判断：这是“把决策与抽取从生成式模型里拆出来”的一个清晰样本。对发票、理赔、路由、风控这类字段固定、调用量大的业务，成本和延迟收益是实打实的；但 preview 阶段、单一 pipeline 自测，正确做法是先影子流量对比，不要直接替换生产判断。

### Meta 披露 Prometheus：百万卡目标、85% goodput 与 99% 中断削减

- 发生了什么：Meta 10-20 02:14 详细披露 Prometheus——位于俄亥俄州 New Albany 的千兆瓦级超算。第一阶段已完成并训练了 Muse 系列基础模型（含 Muse Wonder）；预训练 goodput 超过 85%、强化学习超过 90%，Muse Wonder 训练期间平均无中断时间约 4.7 万 GPU 小时，之后通过固件修复提升到 5.4 万以上。集群目前是跨多栋建筑的数十万张 GPU，目标约 100 万张，并将在 San Miguel 平台引入 Vera Rubin NVL72。
- 为什么值得关注：这是把“算力规模”翻译成运维指标的一次公开课。对超大规模训练来说，一张卡、一个交换机、一条链路出问题就可能拖住整批任务；85% goodput 意味着仍有约 15% 的有效算力被故障、恢复和等待吃掉。电力侧的 30—40% 功率瞬变、几十毫秒内几十兆瓦的摆动，也是其他团队迟早会遇到的问题。
- 核心原帖：[@AIatMeta](https://x.com/AIatMeta/status/2112245968750145561)（10-20 02:14，14.7 万浏览、2,329 赞、182 转、109 回复、63 引用）；[NVIDIA AI Infra](https://x.com/NVIDIAAIInfra/status/2112264876928422128)（5,074 浏览、121 赞）；细节梳理 [@choblin29](https://x.com/choblin29/status/2112275777375101105)（2,307 浏览、24 赞）。
- 核验：对照 [Meta 工程博客](https://engineering.fb.com/2026/10/19/data-center-engineering/inside-prometheus-meta-gigawatt-scale-supercluster/)，确认第一阶段完成、已训练 Muse Wonder、目标约 100 万 GPU、现有数十万张 GPU 跨多栋建筑；85%+ 预训练 goodput、90%+ RL goodput、约 4.7 万 GPU 小时 MTBI（后续 5.4 万+）；2025 年中期峰值接近每天每 8,000 张 GPU 1,000 次中断，一年内削减 99%；为让 32,768 张 GPU 持续训练，实际配置 523 个 NVL72 机架、37,656 张 GPU（约 13% 余量，其中 11% 来自 64/72 的切片几何）；功率瞬变 30—40%，Dynamo Dimmer 做集群级限功率，配合机架电池、电容托盘、储能系统；网络 BAG 跨 2—100 公里。choblin29 的细节基本准确，但“计划扩到约 100 万并加 Vera Rubin”是 Meta 已公开的信息，不是他独家；NVIDIA 所说“cutting interruptions by 99%”与 Meta 一致。需要区分：47K／54K 是 MTBI（平均无中断时间），不是“故障率下降 99%”的同一指标，两者一个看间隔、一个看降幅。
- 判断：这组数字说明，规模上去之后，可靠性工程本身就是模型能力的一部分。备件比例、故障域大小、电力瞬变管理，都会直接变成训练成本和迭代速度。对同业的启示不是“买更多卡”，而是先把 goodput 和 MTBI 当成一级指标；85% 也提醒我们，账面算力和有效算力之间有一道不小的折损。

## 3. 中文 AI 生态

### 网易 LobsterAI 发布第二期办公 Agent 报告：任务变大，入口变微信，账单看缓存

- 发生了什么：网易 LobsterAI 10-19 发布《中国办公 Agent 用户行为报告》（9 月版），这是该系列第二期，并额外统计了十一假期。报告称 9 月单次任务平均消耗 20.2 万 token，是 3 月 6.3 万的 3.2 倍；日均活跃用户 9 月环比增长 83.1%，是 5 月以来最快；泛编程／IT 占任务 40.1%，设计／影视／创作 17.2%；77% 的 IM 派活用户用微信；近七成普通用户只用一个模型。
- 为什么值得关注：这是国内少见的、基于真实产品用户行为而非问卷的 Agent 报告。它给出的方向很具体：任务体量在变大、入口从桌面转向微信、成本差异主要由缓存命中价而不是命中率决定。对做办公 Agent 的团队，这比“模型又涨了几分”更有决策价值。
- 核心原帖：[@dotey](https://x.com/dotey/status/2112194237211029946)（10-19 22:48，1.4 万浏览、63 赞、6 转、32 回复、1 引用）。
- 核验：报告本身未找到公开全文，但 [科技日报](https://www.stdaily.com/web/gdxw/2026-10/19/content_599019.html) 与 [新浪财经](https://finance.sina.com.cn/jjxw/2026-10-19/doc-inivumam6844876.shtml) 10-19 的报道确认了核心数字：DAU 6 月环比 +19.8%、7 月 +25.1%、8 月 +30.6%、9 月 +83.1%；单次任务 6.3 万→20.2 万 token（3.2 倍）；泛编程／IT 40.1%、设计／影视／创作 17.2%；微信 77%；近七成用户单模型、重度用户人均 2.4 个；模型搭配 Top5 全部以 DeepSeek Flash 系列为基座，“+GLM 5.3 Flash”14.0%、“+V4 Pro”12.4%；9 月 token 份额环比 GLM 约 +166.7%、DeepSeek -0.3%、Qwen -18.2%、MiniMax -66.7%、Kimi -78.6%；图像生成 Seedream 57.2%、视频生成 Seedance 54.4%。缓存命中率（DeepSeek V4.1 Flash 97.3% 等）与“实际费用是原价的比例”（4.6% 到 35.1%）只在 dotey 帖和配图中出现，未找到报告全文或第三方复核，按帖文引用，不作为独立核实的数据。DAU 只有环比增幅、没有绝对数，dotey 推算“9 月约为 5 月的 3.6 倍”，报告本身没有这么说。
- 判断：这份报告最值得抄的三点是：任务在变大（token 消耗 5 个月 3.2 倍）、入口在迁移（微信 77%，早上通勤就开始派活）、成本由缓存价决定（命中率都在九成上下，账单却差七倍）。但要记住它是单一产品样本，厂商份额是相对变化不是绝对值；缓存那张表反映的是各家定价策略，不是模型能力。
